# Tecnología web (2026) para visores astronómicos con blink y espectros en el navegador

Notas técnicas para la arquitectura de un visor público que "parpadea" (blink) imágenes SPHEREx de una posición del cielo a lo largo del tiempo, con espectros al vuelo (NASA Space Apps 2026, reto "Planet X and SPHEREx"). Fecha de investigación: 2026-11-08. Términos técnicos en inglés. Todo número de versión/fecha fue verificado contra el registro npm o la página oficial el día de la investigación, salvo que se indique lo contrario.

Convención de confiabilidad: `[npm]` = leído directamente del registry npm (registry.npmjs.org) el 2026-11-08; `[doc]` = documentación oficial; `[inf]` = inferencia propia marcada en la sección de Inferences.

## 1. Aladin Lite v3: versión, integración React/Next.js, API y límites

### Takeaway
Aladin Lite está en la rama 3.x (estable 3.8.2 de marzo 2026; `latest` en npm es `3.9.2-beta`, sep 2026), licencia LGPL-3.0-or-later, requiere WebGL2 y se inicializa con la promesa `A.init`; su API cubre capas HiPS/FITS con `setCuts/setColormap/setOpacity`, catálogos (VizieR/SIMBAD/URL), overlays y eventos (`objectClicked`, `positionChanged`, `zoomChanged`, `stackChanged`). No está diseñado como "blinker" de cutouts; el blink rápido conviene hacerlo en un canvas propio y usar Aladin Lite como panel de contexto (HiPS + catálogos).

### Inferences
- **Integración Next.js (App Router):** como `A.init` toca `window`/WebGL2 y el paquete publica ESM + UMD sin tipos, el patrón correcto es un Client Component (`'use client'`) cargado con `next/dynamic(() => import('./AladinView'), { ssr: false })`, y dentro `useEffect(async () => { const A = (await import('aladin-lite')).default; await A.init; aladinRef.current = A.aladin(divRef.current, {...}) })`. Hay que declarar tipos propios (`declare module 'aladin-lite'`) porque el registry no publica `types`. `[inf]` basado en [npm] y en que `A.init` exige WebGL2 ([A.html](https://cds-astro.github.io/aladin-lite/A.html)).
- Para React StrictMode (doble montaje en dev) conviene limpiar el div en el cleanup o usar un flag `initialized`, porque `A.aladin` sobre el mismo div crea instancias duplicadas. `[inf]`
- **Blink de varias capas:** la API permite tener varias capas (`addNewImageLayer`, `setOverlayImageLayer` con distintos `layer` names) y conmutar `setOpacity(0|1)` en un `setInterval`/`requestAnimationFrame`. Con capas `A.image` FITS ya decodificadas, cambiar opacidad es una operación GPU y debería ser fluida; pero con HiPS el cambio de capa implica tiles de red y Aladin no ofrece un "flipbook" nativo, y `positionChanged`/`zoomChanged` tienen throttle de 100 ms, lo que dificulta sincronizar un canvas externo frame a frame. Recomendación: usar Aladin Lite como **panel de contexto** (HiPS unWISE/NEOWISE/PanSTARRS + catálogos Gaia/SIMBAD + overlay de la trayectoria del candidato) y hacer el blink principal de SPHEREx en un canvas/WebGL propio alimentado por cutouts. `[inf]`
- La versión estable a fijar en noviembre 2026 es **3.8.2** (`npm i aladin-lite@3.8.2`); `latest` en npm apunta a una beta (3.9.2-beta), así que `npm i aladin-lite` sin versión instala una beta. `[inf]` desde [npm]
- **Licencia LGPL-3.0-or-later vs. proyecto MIT:** la LGPL permite usar la librería desde un proyecto MIT sin relicenciar el proyecto, siempre que se conserve la atribución y se permita reemplazar la librería (uso como módulo separado vía npm/CDN cumple esto). Además, los términos de uso de CDS exigen conservar el logo/enlace de Aladin en la vista. `[inf]` sobre la licencia; el requisito del logo es cita directa de [Docs](https://cds-astro.github.io/aladin-lite/).
- `pix2world`/`world2pix` permiten dibujar overlays HTML (tooltips, marcadores del candidato) encima del canvas de Aladin sincronizados con `positionChanged`. `[inf]`

### Gaps
- Lista completa de colormaps y de valores de `stretch` de Aladin Lite: no están en `global.html`; requieren llamar `getListOfColormaps()` o leer el código fuente.
- La documentación no describe un modo "blink"/"animate layers" nativo ni benchmarks de cambio de capa; no encontré pruebas publicadas de fps al alternar capas.
- Firmas detalladas de `setCuts(min, max)`, `setColormap(name, options)` y `setBlendingConfig(additive)` no aparecen en las páginas leídas (solo nombres).
- No se verificó la página de npmjs.com (error de cliente); la info de versiones proviene del registry JSON.

## 2. Ecosistema HiPS: IDs, hips2fits, hipsgen

### Takeaway
Los HiPS de CDS relevantes existen con IDs estables (`CDS/P/unWISE/color-W2-W1W2-W1`, `CDS/P/NEOWISER/Color`, `CDS/P/allWISE/W1`, `CDS/P/2MASS/color`, `CDS/P/DSS2/color`, `CDS/P/PanSTARRS/DR1/color-z-zg-g`, `CDS/P/DM/I/355/gaiadr3`), y hips2fits permite recortes con WCS arbitrario hasta 50 Mpx en FITS/PNG/JPG; no hay un HiPS de SPHEREx en el listado leído, y publicar uno propio implica hipsgen (Java, `Aladin.jar -hipsgen`) y hosting estático con CORS.

### Inferences
- Para el panel de referencia multi-época del visor, los HiPS `CDS/P/NEOWISER/Color` y `CDS/P/unWISE/color-W2-W1W2-W1` sirven como fondo W1/W2 de contexto, pero son coadds (sin resolución temporal), así que **no sustituyen** a los cutouts por época (unwise.me `neo1..neo7`, Legacy `unwise-neo7/neo11`) para detectar movimiento. `[inf]`
- Ejemplo de URL hips2fits para un thumbnail PNG de 300×300 px, 10′ de FoV, colormap viridis y stretch asinh (construida a partir de los parámetros documentados, no copiada de la doc):
  `https://alasky.cds.unistra.fr/hips-image-services/hips2fits?hips=CDS/P/unWISE/color-W2-W1W2-W1&width=300&height=300&fov=0.1667&projection=TAN&ra=83.63&dec=22.01&coordsys=icrs&format=png&stretch=asinh&cmap=viridis&min_cut=0.5%25&max_cut=99.5%25` `[inf]`
- Con `wcs` JSON se puede pedir a hips2fits exactamente la misma grilla WCS (TAN, `CDELT`, `CRPIX`) del cutout SPHEREx, lo que da panels de referencia **pixel-aligned** sin reproyectar en el cliente. `[inf]` apoyado en que `wcs` acepta un diccionario WCS ([hips2fits](https://alasky.cds.unistra.fr/hips-image-services/hips2fits)).
- Publicar un HiPS propio de SPHEREx (p. ej., por banda o por época) requiere un paso offline Java y hosting estático (S3/Cloudflare R2 con CORS); los tiles PNG/JPEG se consumen por Aladin Lite con `A.HiPS('https://tu-host/spherex-hips')`. Para un hackathon esto es viable solo para una región pequeña. `[inf]`

## 3. Otros servicios de cutouts (Legacy Survey, unWISE, PS1, IRSA, SkyView)

### Takeaway
Para paneles de referencia por época, los más útiles son el Legacy Survey viewer (`fits-cutout`/`jpeg-cutout`, hasta 3000 px, capas `unwise-neo7`, `unwise-neo11`, `ls-dr10-south`, `hsc-dr3`, `vlass1.2`, `des-dr1`, `decaps2`, `ztf`) y unwise.me (`cutout_fits?version=neo1|neo2|allwise...&size≤1024&bands=12`, salida tar.gz FITS); PS1 (`fitscut.cgi`, 0.25″/px, ≤6000 px, ≤10 hilos) y SkyView (`cgi-bin/images`, FITS/GIF) completan la cobertura; IRSA recomienda SIA v2 pero la página general no documenta nombres de colección SPHEREx.

## 4. Renderizado FITS/raster en el navegador (JS9, fitsjs, WASM, Firefly, WebGL, Canvas 2D, WebP)

### Takeaway
JS9 está archivado (31 dic 2024, MIT, sin desarrollo desde jul 2022) y las librerías FITS puras en JS están viejas (fitsjs 0.6.6 de 2017) salvo `jsfitsio` 3.1.0 (Apache-2.0, ago 2026); Firefly (IPAC) es potente pero requiere servidor Java/Tomcat; para blink y resta de 150-500 px a 10-30 fps lo más robusto es decodificar FITS a `Float32Array` (propio o con WASM) y renderizar en WebGL (regl 2.1.1 MIT, PixiJS 8.22 MIT, deck.gl 9.4.1 MIT) o Canvas 2D con `ImageData`, aplicando stretch (asinh/log) y colormap en un shader o LUT; WebP solo soporta 8 bits/canal, así que no sirve para transportar datos de 16 bits sin cuantizar.

### Cited Findings
- **JS9**: repositorio archivado por el dueño el **31 de diciembre de 2024** (solo lectura); el README indica que el desarrollo activo terminó el 1 de julio de 2022; último release v3.9.0 (fechas 12/13/2024 en historial vs. 31/12/2024 en README, para corregir la vulnerabilidad del issue #100); licencia **MIT**; soporta FITS, tablas binarias, cubos, MEF, colormaps, escalado, zoom, binning, regiones, blending de imágenes, scripting (pyjs9), Electron, WebAssembly (`astroem.js`, `astroemw.wasm`); el autor pide considerar con cuidado usar un paquete sin mantenedor. — [ericmandel/js9](https://github.com/ericmandel/js9)
- **fitsjs** `0.6.6` (2017-09-14, MIT); **fits-reader** `0.0.8` (2022-11-12, MIT, 37 KB); **jsfitsio** `3.1.0` (2026-08-22, Apache-2.0, 1.29 MB, dep. `cross-fetch`); `astro-fits` no existe en npm; `firefly-api` `2.0.0` (2023-04-29, ISC). — [registry.npmjs.org](https://registry.npmjs.org/jsfitsio) `[npm]`
- **Firefly** (Caltech-IPAC): librería web open source (desde 2015) para archivos astronómicos; tablas probadas con "over 10 million rows, 50 column tables"; visor FITS sin plugins con overlays de catálogos, soporte HiPS; gráficas con Plotly.js; cliente React + Redux; servidor Java/Gradle; requisitos: Java 21, Gradle 8.10, Tomcat 11, Node 26; imagen Docker `ipac/firefly`; API JS permite usar visores "with just a very few lines of JavaScript" y servidor en otro dominio vía JSONP/CORS; docs: `docs/firefly-api-overview.md`, `tutorial/firefly-api-code-examples.md`, `docs/firefly-python-wrapper.md`. El README no indica el tipo de licencia (solo `License.txt`). — [Caltech-IPAC/firefly](https://github.com/Caltech-IPAC/firefly)
- **Librerías WebGL**: `regl` 2.1.1 (2024-11-12, MIT, 1.21 MB unpacked, sin deps); `pixi.js` 8.22.0 (2026-10-01, MIT); `@deck.gl/core` y `@deck.gl/layers` 9.4.1 (2026-10-28, MIT). — [registry.npmjs.org](https://registry.npmjs.org/regl) `[npm]`
- **WWT WebGL engine** (`@wwtelescope/engine`, `engine-pinia`, `research-app`, `embed`...): motor completo de WorldWide Telescope en JS/TS con WebGL; Vue + Pinia (la versión Vuex fue reemplazada); licencia **MIT**, propiedad de .NET Foundation; gobernanza abierta con patrocinio fiscal de NumFOCUS y respaldo de AAS; build sensible a versiones de Node (fallos ~18.17, bloqueos con 20.x en Linux). La página no detalla capacidades FITS/HiPS. — [wwt-webgl-engine](https://github.com/WorldWideTelescope/wwt-webgl-engine)
- **WebP**: canales R, G, B y A de **8 bits**; modo lossless (chunk VP8L); alfa (chunk ALPH o VP8L); ancho×alto ≤ 2^32−1 con campos de 24 bits; la página no menciona 16 bits por canal. — [WebP RIFF container](https://developers.google.com/speed/webp/docs/riff_container)
- **Accesibilidad de canvas**: el canvas es solo un bitmap; MDN recomienda contenido de respaldo dentro de `<canvas>`, atributos ARIA (`role`, `aria-label`, `tabindex`), sub-DOM enfocable, `drawFocusIfNeeded`; la API de hit regions (`addHitRegion`) es experimental y no debe usarse en producción. — [MDN Hit regions and accessibility](https://developer.mozilla.org/en-US/docs/Web/API/Canvas_API/Tutorial/Hit_regions_and_accessibility)

### Inferences
- **Pipeline recomendado para blink SPHEREx** `[inf]`: (1) servidor (Route Handler Next.js o worker Python con astropy) recorta y entrega cada época como `Float32Array` binario (`application/octet-stream`, little-endian) o como PNG 16-bit gris + metadatos `{bzero,bscale,min,max}` en JSON; (2) en el cliente, un único `<canvas>` WebGL con regl: una textura `R32F`/`R16` por época (150×150..500×500 px → 90 KB..1 MB float por frame, trivial en VRAM), uniformes `uMin,uMax,uStretch,uColormapLUT`; el blink es cambiar la textura ligada por frame en `requestAnimationFrame` (10-30 fps sin problema); la **diferencia** A−B es un fragment shader con dos texturas. (3) Colormaps viridis/cividis/magma como textura 1D de 256×1 RGBA (LUT); stretch asinh/log/sqrt en el shader: `asinh(x)` = `log(x + sqrt(x*x+1))` si GLSL ES 3.0 no expone `asinh` (WebGL2/GLSL ES 3.00 sí lo expone como built-in). (4) Percentile cuts (p. ej. 0.5%/99.5%) se calculan en CPU con un histograma de 65536 bins sobre el `Float32Array` (≤250k píxeles → <5 ms).
- Canvas 2D es suficiente como fallback: precomputar por frame un `ImageData` (Uint8ClampedArray RGBA) tras aplicar stretch+LUT en JS y usar `putImageData` o `drawImage` desde `OffscreenCanvas`; para 500×500 (250k px) el remapeo en JS toma pocos ms en hardware moderno, así que 30 fps es alcanzable si el remapeo se hace **una vez por cambio de cuts**, no por frame. `[inf]` (sin benchmark publicado encontrado; afirmación propia).
- Transportar datos ~16 bits: PNG 16-bit escala de grises (lossless, 1 canal) o un binario Float32/Int16 con `Content-Encoding: br/gzip` son mejores que WebP (8 bits). AVIF sí soporta 10/12 bits, pero no se verificó en esta investigación y no es lossless 16-bit; se recomienda el binario crudo. `[inf]`
- Para leer FITS directamente en el navegador, `jsfitsio` (Apache-2.0, activo 2026) es la opción con mantenimiento; Apache-2.0 es compatible con un proyecto MIT (se conserva aviso y NOTICE). JS9 (MIT) puede usarse como referencia de algoritmos (zscale, colormaps) pero no como dependencia de producción por estar archivado. `[inf]` sobre compatibilidad de licencias.
- Firefly no encaja en un stack serverless Next.js para un hackathon (requiere Tomcat/Java 21); se recomienda solo como referencia de UX (Rubin Science Platform Portal). `[inf]`

### Gaps
- No encontré benchmarks publicados y recientes de fps para blink de 150-500 px en Canvas 2D vs WebGL; las estimaciones anteriores son propias.
- No verifiqué `fitsio-wasm` ni bindings WASM de cfitsio en npm (no se buscó por falta de llamadas).
- Licencia exacta de Firefly: no visible en el README (hay `License.txt`); versión actual no indicada.
- WWT: la página del repo no confirma soporte FITS con stretch en el cliente ni la versión más reciente.
- AVIF: profundidad de bits y modo lossless no verificados en esta sesión.

## 5. Librerías de gráficas para espectros y curvas de luz en Next.js

### Takeaway
Para espectros y light curves interactivos en Next.js, uPlot (1.6.32, MIT, ~50 KB min, Canvas 2D, muy rápido pero sin animaciones ni scatter nativo) y Observable Plot (0.6.19, ISC, SVG, excelente para errores/bandas) son las opciones ligeras; Plotly.js (4.2.0, MIT, ~6.2 MB dist-min) y ECharts (6.1.0, Apache-2.0) son pesadas pero completas; Recharts (3.10.1, MIT) es cómodo en React pero depende de Redux/immer y es el menos eficiente para muchos puntos.

- `uplot` 1.6.32 (2025-03-14, MIT, 545 KB unpacked, sin deps). Wrappers React de terceros (`skalinichev/uplot-wrappers`). — [leeoniya/uPlot](https://github.com/leeoniya/uPlot); [registry](https://registry.npmjs.org/uplot) `[npm]`

## 7. Implementaciones de referencia (Legacy Survey viewer, ESASky, WWT, Firefly/RSP, brokers, Zooniverse)

### Takeaway
Los patrones a estudiar son: Legacy Survey viewer (Leaflet + Django tiles + cutouts, BSD-3), ESASky (GWT→migración a Angular, AGPL-3.0, embebe Aladin Lite), WWT (MIT, Vue/Pinia), Firefly (React/Redux + Plotly, servidor Java) y los brokers (Fink: Dash/HBase, Apache-2.0; Lasair: mapa de alertas + tabla + páginas `/objects/<id>/`), que convergen en la UX "stamps science/template/difference + light curve + crossmatch + Aladin"; Zooniverse aporta el flipbook con velocidades y miniaturas.

### Cited Findings
- **Legacy Survey viewer (imagine)**: Django + uWSGI, LeafletJS, tiles JPEG prerenderizados, BSD-3-Clause; cutouts hasta 3000 px. — [legacysurvey/imagine](https://github.com/legacysurvey/imagine); [views.py](https://raw.githubusercontent.com/legacysurvey/imagine/main/map/views.py)
- **ESASky**: frontend de sky.esa.int/esasky construido con GWT, migración en curso a Angular (se publicará cuando esté casi terminada), build Maven, módulos `aladinlite-widget`, `esasky-cl`, `esasky-cl-mission-planning`, `esasky-model`; despliegue en Tomcat (puerto 8080); licencia **AGPL-3.0**; 2,553 commits. — [esdc-esac-esa-int/ESASky](https://github.com/esdc-esac-esa-int/ESASky)
- **WWT WebGL engine**: MIT, Vue + Pinia, NumFOCUS/AAS/.NET Foundation; paquetes `@wwtelescope/engine`, `engine-pinia`, `research-app`, `embed`, `embed-creator`. — [wwt-webgl-engine](https://github.com/WorldWideTelescope/wwt-webgl-engine)
- **Firefly** (base del Rubin Science Platform Portal): React/Redux, Plotly.js, Java 21/Tomcat 11, Docker `ipac/firefly`. — [Caltech-IPAC/firefly](https://github.com/Caltech-IPAC/firefly)
- **Fink Science Portal**: backend Apache HBase indexado por `objectId` y `jd`, tablas índice por tiempo/posición/clasificación; frontend **Dash** (Flask + Plotly + React); callbacks `on_load_lightcurve` (Graph) y `display_skymap` (`aladin-lite-div-skymap`); nifty-ls para variables, Miriade (IMCCE) para objetos del Sistema Solar; Python 3.9-3.11; licencia **Apache-2.0**; datos "as of 01/2025". — [astrolabsoftware/fink-science-portal](https://github.com/astrolabsoftware/fink-science-portal)
- **Lasair-ZTF**: UI con Filters, Watchlists, Watchmaps, Annotators, Schema Browser; mapa de alertas recientes (<17 mag) coloreado por tipo (Possible Supernova, Nuclear Transient, CV, AGN) sobre fondo "Mellinger color optical survey"; tabla (objectId, ramean, decmean, gmag, rmag, last detected, predicted type) exportable CSV/JSON; páginas `/objects/<id>/`; campos TNS Id, TNS Associated Names, Host Galaxy; docs en lasair.readthedocs.io; desarrollado por U. Edinburgh y QUB, financiado por STFC. — [lasair-ztf.lsst.ac.uk](https://lasair-ztf.lsst.ac.uk/)
- **ALeRCE** (arXiv:2008.03303, 2020-08-07): broker liderado por Chile con pipeline de ingesta, cross-matching, clasificación ML (stamp classifier y light-curve classifier) y visualización del flujo ZTF; cifras del resumen: 9.7×10⁷ alertas, 1.9×10⁷ objetos clasificados por stamps, 3088 candidatos a SN. — [arXiv:2008.03303](https://arxiv.org/abs/2008.03303)
- **ANTARES** (arXiv:2011.12385, v2 2021-01-13, AJ, DOI 10.3847/1538-3881/abd703): anota alertas con asociaciones a catálogos y filtra subconjuntos; el paper describe modelo de datos, arquitectura, anotación, filtros, provenance, desempeño e interfaz. — [arXiv:2011.12385](https://arxiv.org/abs/2011.12385)
- **Zooniverse FlipbookViewer**: ver sección 6. — [README](https://raw.githubusercontent.com/zooniverse/front-end-monorepo/master/packages/lib-classifier/src/components/Classifier/components/SubjectViewer/components/FlipbookViewer/README.md)

### Inferences
- **Compatibilidad de licencias con un proyecto MIT**: se pueden *copiar/adaptar código* de imagine (BSD-3), WWT (MIT), JS9 (MIT), Zooniverse (ver gap), Fink (Apache-2.0 con NOTICE); **no** conviene copiar código de ESASky (AGPL-3.0: obligaría a liberar el servicio completo bajo AGPL) y Aladin Lite (LGPL) solo se usa como dependencia, no se copia dentro del bundle MIT. `[inf]`
- La UX común de brokers (triplete de stamps + light curve + Aladin + crossmatch) se traslada directo al visor SPHEREx: triplete = época A / época B / diferencia; light curve = flujo por época/banda; crossmatch = Gaia DR3 (VizieR I/355) y SIMBAD vía `A.catalogFromVizieR`/`A.catalogFromSimbad`; panel Aladin con HiPS unWISE/NEOWISE. `[inf]`
- Fink y Lasair muestran que un backend Python (Dash/Django) es viable, pero para Next.js + Vercel el patrón más cercano es Legacy Survey (API de cutouts stateless + cliente ligero). `[inf]`
